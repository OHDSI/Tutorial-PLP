PatientLevelPrediction with Strategus

1 Overview

This document shows how to:

  • Load cohort JSONs and generate cohorts using CohortGenerator.
  • Configure a PatientLevelPrediction (PLP) design.
  • Assemble Strategus analysis specifications
  • Execute the analysis specifications against a DuckDB Synthea example database.

This is the tutorial reference. To run the tutorial we recommend using the R file which can be downloaded along with the cohorts in a zip file from here. This file contains the same code but is easier to run and modify step-by-step. Please start a new R project and extract the contents of the zip file into the project folder.

First we need to set up our environment.

cohortDefinitions[1, ] <- list(

4 PLP Design

This section configures the PLP design by defining covariates, population settings, preprocessing, data splits, and the baseline model choice.

TipModel Variations
Code 
1covariateSettings <- FeatureExtraction::createDefaultCovariateSettings()

populationSettings <- createStudyPopulationSettings(
  binary = TRUE,
  removeSubjectsWithPriorOutcome = TRUE,
  requireTimeAtRisk = FALSE,
  riskWindowStart = 1,
  riskWindowEnd = 30,
2)

preprocessSettings <- createPreprocessSettings(
  minFraction = 0.001,
  normalize = TRUE,
  removeRedundancy = TRUE
3)

4splitSettings <- createDefaultSplitSetting(splitSeed = seed)

# Choose model based on parameter (baseline: lasso logistic)
5modelSettings <- PatientLevelPrediction::setLassoLogisticRegression(seed = seed)
  # Other options (require additional packages; see Exercises below):
  # PatientLevelPrediction::setGradientBoostingMachine(ntrees = 100, seed = seed),
  # PatientLevelPrediction::setRandomForest(ntrees = 100, seed = seed),

message(sprintf("Model selected: %s | Split seed: %s", "LASSO", seed))

modelDesign <- PatientLevelPrediction::createModelDesign(
  targetId = 1,
  outcomeId = 2,
  populationSettings = populationSettings,
  covariateSettings = covariateSettings,
  preprocessSettings = preprocessSettings,
  modelSettings = modelSettings,
  splitSettings = splitSettings,
  runCovariateSummary = TRUE
6)

plpModule <- PatientLevelPredictionModule$new()
7plpModuleSpecs <- plpModule$createModuleSpecifications(modelDesignList = modelDesign)
1
Generate a broad set of default covariates using FeatureExtraction.
2
Define cohort eligibility and the time-at-risk window.
3
Configure preprocessing to normalize features and drop redundancy.
4
Fix the train/test split seed for reproducibility.
5
Choose the baseline LASSO logistic regression model (swap here to explore alternatives).
6
Assemble the pieces into a complete model design.
7
Wrap the design in a PLP module specification Strategus can execute.

6 Execution settings and running

Create the execution settings, point Strategus to your DuckDB database, and then run the analysis.

WarningBefore You Run
Code 
# Define where Strategus should store intermediate work files and final results
1workFolder <- "./results/strategus/work"
resultsFolder <- "./results/strategus/results"

executionSettings <- Strategus::createCdmExecutionSettings(
  workDatabaseSchema = workSchema,
  cdmDatabaseSchema = cdmSchema,
  cohortTableNames = CohortGenerator::getCohortTableNames(cohortTable = cohortTable),
  workFolder = workFolder,
  resultsFolder = resultsFolder,
  incremental = FALSE
2)

connectionDetails <- DatabaseConnector::createConnectionDetails(
  dbms = "duckdb",
  server = dbPath
3)

# Execute the study (may take some minutes depending on data size)
Strategus::execute(
  analysisSpecifications,
  executionSettings = executionSettings,
  connectionDetails = connectionDetails
4)

Define where Strategus should store intermediate work files and final results.
2
Build execution settings that contain schemas, cohort tables, and output locations.
3
Supply connectionDetails for Strategus to reach your database.
4
Kick off the Strategus pipeline with the assembled specifications.

8 Exercises

TipReset Between Runs

If you plan to re-run the exercises with different settings, remove the contents of ./results/strategus/work/PatientLevelPredictionModule/ between runs so PLP does not skip running. Adjust the path if you used a different workFolder.

  1. Explore Coefficients and Top Predictors: After running the analysis, use the PLP viewer to inspect the model coefficients and top predictors. How do these align with your expectations?

  2. Model Exploration: Modify the modelSettings in the PLP design section to experiment with different algorithms like Random Forest (setRandomForest) or XGBoost (setGradientBoostingMachine). Make sure to choose a subset of hyperparameters so it doesn’t run forever. Observe how these changes impact model performance metrics.

    Pay attention to how more flexible models influence training versus test performance and whether additional tuning is required.

  3. Seed Variation: Change the seed variable to different values and rerun the analysis. Document how the results vary with different seeds, particularly focusing on model stability and performance consistency. What do you think is affecting the variablitiy in our case?

  4. Network study: Share your analysisSpecifications.json file with a colleague and have them run your analysis.

  5. Go Deep: Try to develop a deep learning model using setDefaultResNet from the DeepPatientLevelPrediction package. Install it first with install("DeepPatientLevelPrediction"). Note either on install or first run it will take a few minutes to set up the python dependencies.
